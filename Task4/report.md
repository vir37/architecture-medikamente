# Отчет по выявленным проблемам текущей реализации и предлагаемым решениям указанных проблем

1. **Проблема**: Недостаточное количество IT-специалистов.<br>
	Очевидно, что для поставленных масштабных задач имеющихся в штате специалистов недостаточно.<br>
   **Решение**:	Вариант 1 - нанять стороннюю компанию для разработки модулей, описанных предлагаемой архитектурой. Дальнейшее сопровождение осуществлять силами имеющихся специалистов. <br>
				Вариант 2 - набрать в штат специалистов с компетенциями в выбранном стеке технологий. Этот вариант предпочтительнее, так как продукт с большой долей вероятности будет развиваться и далее.
2.	**Проблема**: Недостаточная квалификация IT-специалистов в выбранном стеке технологий.<br>
	Компетенции имеющихся специалистов будет недостаточно для сопровождения нового решения. Т.к. предполагается внедрение сторонних коммерческих продуктов (Collibra например).<br>
	**Решение**: В обязательном порядке провести обучение имеющихся специалистов по тем предлагаемым решениям, с которыми они не знакомы. В случае найма для разработки микросервисов сторонней компании, обязательно обучить и стеку технологий будущего решения.
3.	**Проблема**: 1 сервер, нет резервирования.<br>
	Одного сервера, очевидно, не хватит для развертывания нового решения. Более того, в текущем решении отсутствуют какие-либо механизмы по обеспечению отказоустойчивости.<br>
	**Решение**: Проанализировать потребности нового решения в ресурсах с учетом запаса мощности и обеспечения отказоустойчивости. Предусмотреть организацию полноценного серверного помещения.<br>
	Альтернативой может быть аренда мощностей в каком-либо внешнем ЦОД либо перенос сервисов в облако.
4.	**Проблема**: Модель доступа реализуется только средствами файловой системы.<br>
	Текущее решение, помимо проблем с управлением, несет в себе проблему неочевидных прав доступа, требующихся в бизнес-процессах. Может случиться так, что при реализации в новом решении модели доступа RBAC какие-то необходимые права могут быть не учтены.<br>
	**Решение**: Тщательно проанализировать имеющиеся в компании бизнес-процессы и их участников. Составить карту доступа к имеющимся ресурсам.
5.	**Проблема**: Имеющиеся каналы связи не рассчитаны на интенсивное использование.<br>
	Имеющиеся каналы связи (как LAN, так и WAN) рассчитаны на низкое сетевое взаимодейтствие. Может случиться так, что имеющееся оборудование не справится с сетевой нагрузкой нового решения.<br>
	**Решение**: Исходя из предполагаемых потребностей нового решения в сетевом взаимодействии предусмотреть расширение внешних каналов связи, а также обновление сетевого обородования компании.
6.	**Проблема**: Продукты 1С функционируют в файловом режиме.<br>
	Такое решение не масштабируется, сложно реализуется новая модель доступа с аудитом.<br>
	**Решение**: Предусмотреть перевод продуктов 1С на работу с СУБД. В идеале провести разделение на микросервисы для возможности горизонтального масштабирования.<br>
7.	**Проблема**: Имеющиеся наработки в получении аналитических отчетов завязаны на Excel.<br>
	Все имеющиеся в текущем решении наработки в части аналитических отчетов построены на получении данных из Excel-файлов. При переходе на новое решение эти отчеты работать не будут.<br>
	**Решение**: Провести тщательный анализ имеющихся аналитических отчетов и источников данных для них. Подготовить миграцию их на новые источники и структуры данных.
8.	**Проблема**: Хранилище информации в виде разрозненных файлов Excel.<br>
	Вся имеющаяся база данных о пациентах представлена разрозненными файлами Excel. Часто информация в них дублируется. Важно не потерять при миграции имеющиеся данные.<br>
	**Решение**: Провести тщательный анализ имеющихся источников данных, составить по ним схему данных. Новую структура данных проработать так, чтобы заранее выделить в ней ту часть, которая представляет собой конфиденциальную информацию.
9.	**Проблема**: Отсутствие современного механизма взаимодействия с лабораторией.<br>
	Судя по всему в настоящем решении результаты анализов передаются из лабораторий по электронной почте. От такого решения планируется уходить. Но очень важно проследить, чтобы лаборатории были готовы взаимодейстовать с компанией через новые механизмы.<br>
	**Решение**: При проработке в компании нового сервиса для взаимодействия с лабораториями важно держать постоянную связь с партнерами, согласовывать с ними внедряемое решение, мониторить готовность лабораторий к новому взаимодействию.
10. **Проблема**: Отсутствуют практики CI/CD.<br>
	Проблема может показаться несущественной. Однако при дальнейшем развитии новых продуктов или даже просто устранении выявленных багов (а они точно будут, особенно на старте) отсутствие этих практик может существенно тормозить выпуск новых релизов.<br>
	**Решение**: Прокачать компетенцию имеющихся IT-специалистов.
11. **Проблема**: Отсутствуют практики и внутренние ресурсы компании для обучения персонала.
	Отсутствие внутренних ресурсов компании с какими-либо методическими и обучающими материалами может негативно сказаться на темпах запуска нового продукта: это что-то совершенно новое, а почерпнуть информацию по нему можно только у разработчиков.<br>
	**Решение**: Предусмотреть в новом решении развертывание внутри компании WIKI-системы. Обеспечить своевременное наполнение её необходимыми сотрудникам обучающими и информационными материалами. Провести обучение сотрудников по правилам работы с WIKI-системой.
12. **Проблема**: Аналитика по платежам строится на основе дублирующейся информации в Excel.
	Кассиры дублируют информацию об оплатах услуг в Excel-файл для возможности последующего использования её имеющимися инструментами построения аналитических отчетов. После перехода на новую архитектуру информация о платежах будет храниться только в 1С. Отчеты перестанут работать.<br>
	**Решение**: Предусмотреть в новой аналитической системе отчетов интеграцию с 1С (посредством непосредственного взаимодействия с БД или введения в архитектуру решения, основанного на EventSourcing).
